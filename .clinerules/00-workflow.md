# GymCore — рабочие правила (всегда активны)

## Язык и стиль ответа

- Отвечай **по-русски**, кратко и по делу. Код, идентификаторы, коммиты, имена файлов — по-английски.
- Не пересказывай прочитанные файлы и не выводи код, который не изменился.
- Максимум в 1 вопрос за ответ, в конце. Если можно продолжить по плану — продолжай, не блокируйся.

## Протокол начала задачи

1. Контекст берём из `memory-bank/`, а не из повторного чтения репозитория: сначала `memory-bank/activeContext.md`, при необходимости `memory-bank/progress.md`. Больше 2 файлов на старте — уже перебор.
2. Перед правками озвучь план в 3–6 строк (файлы + суть). Если задача больше 2 файлов или меняет архитектуру — сначала план и согласование, без правок.
3. Читай только нужное, точечно (для больших файлов — диапазоны строк). Не сканируй репозиторий и `node_modules` целиком; для широкой разведки проси субагентов (`use_subagents`).
4. Неизвестный API Next.js — сначала гайд в `node_modules/next/dist/docs/` (карта в скилле `gymcore-next16`), потом код.

## Протокол завершения задачи

1. Проверка: скилл `gymcore-verify` (tsc → eslint → build, компактный отчёт). Не считать задачу выполненной без зелёной проверки.
2. Обнови `memory-bank/activeContext.md` (ветка, статус, что сделано, следующие шаги, открытые вопросы). Этап закрыт → ещё `progress.md`.
3. Итог: что изменилось (файлы) → как проверено → что дальше. Без воды.

## Жёсткие ограничения (нарушать нельзя)

- **Никаких** `git commit` / `git push` / `git reset` / `git checkout --` без явного разрешения пользователя.
- **Не запускать** `drizzle-kit push|generate|migrate`. Схема — только `db/schema.sql` + `db/indexes.sql` (`CREATE TABLE/INDEX IF NOT EXISTS`, идемпотентно). Скилл `gymcore-db`.
- **Не трогать** блок `<!-- BEGIN:nextjs-agent-rules --> … <!-- END:nextjs-agent-rules -->` в `AGENTS.md` — его перегенерирует `next dev`. Не удалять `CLAUDE.md` (`@AGENTS.md`).
- **Не читать и не печатать** `.env.local`; переменные брать из `.env.example`.
- Миграции БД — только аддитивные и идемпотентные; никакого изменения/удаления существующих данных или столбцов.
- Не переписывать существующую незакоммиченную работу в worktree (список — в `activeContext.md`).

## Экономия токенов (= качество)

- Правки — маленькими точечными diff'ами, не перезаписывай файл целиком.
- Повторяющуюся рутину не переспрашивай: она в скиллах `.cline/skills/` (verify / i18n / db / next16).
- Проверка — через скрипт (`gymcore-verify`), а не серией команд: полный вывод `next build` в контекст не нужен.
- Массовую механическую работу (много файлов одного типа) отдавай субагентам, чтобы не раздувать основной контекст.
- Если задача превращается в длинную (>7–8 шагов) — предложи `/newtask` с выжимкой в `activeContext.md`.
